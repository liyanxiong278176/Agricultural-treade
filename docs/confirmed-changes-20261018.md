# 2026-10-18 操作流程调整

用户完成 grill-with-docs 逐项访谈后明确回复“确认”，授权实施本文件与 change-interview-20261018.md 所记录的方案。本文件优先于以前版本中冲突的派工、计费保存、扣皮、归属更正、结算付款和列表展示规则。

## 计费与派工

- 修改产品计费规则可以直接保存。“试算工资”为可选辅助，不作为保存前置条件。保存时必须检查调整原因、日期、阶段类型、金额、数量限制、历史结构兼容及追溯降价保护，明确显示错误。
- 每日派工功能移除，不再显示页面、入口或发送派工队列。旧派工表、本机旧队列数据保留，不继续执行；旧 API 返回410。不会因为移除派工删除有效采摘量或工资。

## 重量配置与扣皮

- 老板和记录员均可进入“重量配置”，分别维护毛重选项和筐型单筐皮重。记录员不因此获得账号、产品规则或付款管理权限。
- 不启用扣皮时，继续直接填写采摘净重。
- 启用扣皮时分别选择已维护的毛重和筐重，填写本次实际容器数量；不能在录入表单临时覆盖配置值。实际重量输入保留在扣皮卡片下方，只读。
- 实际重量＝毛重－单筐重×容器数量；负净重不允许保存。容器数量仅用于扣皮，不额外产生计件工资。
- 配置以公斤维护，显示和提交按所选斤、公斤、克换算。服务端重算净重，不信任客户端提交的净重。
- 配置保存历史版本。后续配置变化不改写历史数量，也不使已经选好旧版本的离线记录被换成新重量。新协议验证配置编号、版本与重量一致；旧离线协议仍可按原形状补传，不改写既有操作内容摘要。

## 归属更正

- 去掉单独的“正确地块”。只有一个数量组成时直接修改“本次所属班组”和“本次地块”；多个组成时先选择要移动的一项。
- 更正仅移动选中组成的全部数量，其他组成保持不变。目标已存在同组同地块组成时合并数量。
- 更正必须填写原因，并校验原记录版本；支持按原离线协议补传。总数量、工资及历史账目快照不变。
- 仅改地块不使每日签字失效；班组变化后，按原有班组核对规则要求重新核对。

## 工资与付款

- 工资页面移除“待结算差额”“已付”字段及独立月结、补结算按钮。累计付款事实仍保存在付款明细与审计中，不删除。
- “已确认应发”展示当前有效记录及适用规则的核算工资；“未付”＝当前应发－累计实际付款。金额更正后刷新即可更新，不需再次确认差额。
- 老板直接登记实际付款。服务端在月份锁与同一事务内重新计价、校验未付、为该工人保存新增账目差额快照并登记付款，不替其他工人确认账目。
- 同一付款ID相同内容重传只执行一次，内容变更拒绝。并发付款不能超过最新未付；失败时快照、付款和审计整笔回滚。
- 原付款与历史快照不可改写。记录更正仍需原因、权限及版本校验；已经纳入历史快照的记录不能直接删除。
- 多付允许显示：应发1000元、付600元后显示应发1000元、未付400元；更正应发1200元后显示未付600元。若付1000元后更正为900元，显示未付-100元并提示线下处理，不自动退款。
- 旧结算 API 及内部历史差额保留兼容原快照与历史测试；新前端不需要调用独立确认接口。

## 查询、分页、打印与离线

- 页面主列表及弹窗明细提供查询、分页，总数、页码及每页条数。默认20条，可选10/20/50条，修改查询条件后回到第一页。
- 采摘账本按工人、工号、产品、时段、班组、日期查询；资料按关键字和启停状态；工资按工人及未付/付清/多付；地块成本按地块和产品；每日核对按日期、班组、签字状态及工人；日志、付款与快照按各自关键字查询。
- 在线持久业务列表使用服务端分页读接口，记录ID先分页再读取详情。工资及地块等派生列表先按业务口径计算，再由服务端返回匹配页，不把屏幕分页当成统计范围。
- 导入预览、本机同步队列和已经取回的不可变打印版本按本机数据查询分页。离线只查询该账号已经下载的数据，显示范围提示，不冒充农场全量结果。
- 打印、导出包含当前查询条件的全部数据，不只取当前页。每日核对保留完整工人当天账目和打印前指纹校验。
- 下拉选项、规则阶段编辑及图表不作为分页业务列表；离线所需的基础资料和月度记录仍下载缓存。
- 正式入口预缓存页面及构建资源。开发入口另外启用Service Worker并准备开发模块，避免只有页面外壳而刷新后缺少脚本。API不进入页面静态缓存。
