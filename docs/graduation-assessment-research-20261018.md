# 毕设适足性：公开评价标准与农业场景调研

调研日期：2026-10-18。研究对象为当前“田间账本·农场采摘计件计重管理系统”，依据根目录 README.md 与 docs/requirements.md 理解业务范围。本笔记提供外部资料与判断框架，不代表本校评分结论，不证明代码全部正确。

## 一、调研方法及适用边界

优先采用高校官方网站、政府公开文件与厂商产品原始说明。已读取 research 与 agent-reach 技能，按后者 search reference 尝试 `mcporter call 'exa.web_search_exa(...)'`，环境返回 `Unknown MCP server 'exa'`，因此改用内置网页搜索与打开工具。厂商网页只用来说明行业已有能力，不采用营销效果数字。Agent Reach 更新检查因 GitHub API 速率限制未完成。

用户未提供学校、专业培养要求、任务书与当届评分表。以下高校制度发布于 2019—2021 年，只作为公开样例展示共同评价维度；不能把其中分数权重、论文字数或查重阈值直接套用到本项目。实际验收以用户本校当前规定和导师要求为准。

## 三、基于当前需求范围的判断

**推断：若按普通本科计算机/软件工程应用系统设计类毕设衡量，当前范围具备充足工作量和可展开的工程深度；不足主要需要从证据和成果表达中查找，不宜先增加业务模块。** 这是根据当前文档与上述评价维度作出的判断，不是学校通过承诺。

当前文档已经描述基础资料、派工、记录、计薪、离线同步、纠错、结算付款、地块人工成本、Excel 导入、纸表核对和审计。更值得作为论文主线的是三个贯穿业务的难题：

- 弱网及结果未知情况下，以固定操作 ID、队列事务与回执避免丢单和重传重复执行；业务重复仍由业务唯一键区分。
- 多记录员协作与结算并发，通过版本校验、冲突处理、月份行锁及事务协调记录与结算。
- 价格版本、数量更正、晚传数据与已确认账单并存，使用不可改写快照和补结算差额保留历史。

这些是标准技术在具体农业流程中的组合应用，可以表述为系统设计特色、应用改进或工程难点；不能写成发明了幂等、乐观锁或全新结算算法。前后端分离、图表和 Excel 导出本身也不足以支撑创新性。

## 四、建议优先补充的成果

1. **量化实验。** 明确规模、设备、数据量和网络条件，报告接口 P95 延迟、积压同步耗时、重传重复执行数、冲突检测及恢复情况、结算金额与独立预期结果的偏差。根据单基地实际量级设计实验，不为高并发数字扩大架构。现有功能用例不能代替性能结论。
2. **可核对的用户评估。** 请少量实际老板/记录员在授权测试数据上完成同一组纸表/Excel 与系统任务，保留完成时间、错误数、操作失败及反馈。小样本用于发现问题，不包装为有统计代表性的行业结论。
3. **实机与纸面闭环。** 安卓受信 HTTPS、断网重开、恢复网络补传、两人冲突和实体打印分别留证。桌面模拟不等于目标安卓实机通过，浏览器预览不等于打印纸张验收完成。
4. **运行维护。** 备份与恢复演练应优先于新增聊天机器人或大屏，证明离线队列、服务端账单及导出文件的恢复边界。是否已有实现需由代码审查确认。
5. **论文与答辩。** 提供需求依据、规则优先级、架构与数据模型、状态/时序图、方案取舍、实验设计与局限。演示围绕“断网录入—补传—冲突—更正—补结算—核对”展开，展示关键证据。

若确有余力，可讨论异常数据核对提醒或数据质量报告，但应由实际需求驱动并确认规则；不自动引入二维码、电子秤、审批流、工人账号或改变现有结算周期。政府招聘公告中的半月发薪不能擅自覆盖本项目已确认的月度结算规则。
