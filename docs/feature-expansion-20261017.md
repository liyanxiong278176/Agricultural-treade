# 农场用工功能扩展确认稿

日期：2026-10-17。状态：用户已于本次访谈最终确认并授权实施；功能已接入，验证见 expansion-verification-20261017/REPORT.md。逐次确认依据见 discovery.md“新增功能访谈”及决策 1–42；最后列出的默认细则已随确认稿获得整体确认。

## 一、范围

本轮实施方向为四项：每日作业名单与派工、地块/大棚与人工成本、基础资料批量导入、核对表打印快照。

原选定的“纠错申请与处理状态”已由用户取消。疑问在线下核实，确定后直接更正；系统保留原因和操作经过，不新增申请审批流程。

沿用电脑与安卓响应式、本地演示、无二维码、工人不开账号、计件与计重计薪的现有范围。本轮未增加计时、计日工资或电子秤接入。

## 二、每日作业名单与派工

- 老板、记录员均可建立和调整名单，保留操作人及修改经过。
- 安排包含实际日期、上午/下午、工人、班组、产品、地块/大棚。同一工人同一时段可有多项安排。
- 不填写目标采摘量，名单本身不产生工资。
- 未提前安排也允许登记真实采摘量，并标记“未在作业名单”供核对。
- 出现匹配的实际采摘记录后自动显示“已有记录”，无需逐项点击确认；该状态不代表全部数量已经录完。
- 临时变更保留原安排，记录原因及实际去向，显示“已变更”，不将原安排继续列为待查漏记。
- 未实际作业可由老板或记录员登记请假、未出工、安排取消等原因，留痕后完成该项说明。没有记录也没有说明时显示“待核对”，不能自动认定漏记或扣薪。
- 已完成离线准备的设备断网时可查看已下载名单和地块资料、继续登记采摘量，也可以修改派工名单；本机保存后联网上传。多人修改冲突须核对，不能静默覆盖。

## 三、地块数量和人工成本

### 数量归属

保留“工人 + 实际日期 + 上午/下午 + 产品”的原时段唯一记录。不按地块新增同级采摘记录。

每次增加量同时注明实际班组与地块，形成相互对应的数量组成；各组成合计等于原记录总量。既能按班组查询，也能按地块查询。

旧记录缺少地块时保留“未指定地块”，不猜测地块；新录入也允许暂未指定地块，提醒后续补齐。报表单独列出未指定数量及成本。原数量与工资不变。

### 成本分摊

| 计费方式 | 已确认分摊规则 |
| --- | --- |
| 纯计重 | 按各地块净重占比分摊该记录最终工资 |
| 纯计件 | 按各地块计薪筐数占比分摊该记录最终工资 |
| 分段登记混合计费 | 各阶段按地块该阶段数量分摊阶段金额，再汇总地块成本；筐数与重量不混加 |
| 总重量顺序分配 | 先对总量执行原计费规则，再按各地块净重占比分摊成本；不按地块分别折算筐数或重复计薪 |

分摊仅表达采摘人工成本归属，不改变工人总工资。金额按分展示，分摊合计严格等于原记录工资，不代表包含全部农场经营费用。尾差分配具体方式尚待整理确认。

### 地块更正与数量更正

只选错地块时，可将对应数量和人工成本转移到正确地块，填写原因、保留经过，总数量、工人工资及原结算账单不变。

记录员可查看其他记录员历史采摘记录，并直接更正本人或他人记录的地块归属和采摘数量，包含往日、已结算记录。原因必填，保留修改前后值、操作人及版本校验。

数量更正引起工资差额时，保留原结算快照，差额另行补结算。此项不授予记录员确认结算、补结算、付款、发布单价或直接删除已结算记录的权限。原有其他删除规则不变。

设备已下载原记录时，往日及已结算记录的数量更正也可离线填写原因并保存，联网后按原操作标识、原版本校验提交；冲突需核对。本机保存只代表待同步，后台确认后才更新正式账目和工资差额。

## 四、批量导入

### 对象与权限

| 资料 | 新增 | 已有资料处理 |
| --- | --- | --- |
| 工人 | 支持 | 已有工号一律跳过，更新仍手动处理 |
| 班组、产品类别、产品、地块/大棚、筐型 | 支持 | 展示差异，明确确认后可更新 |

老板和记录员均可执行上述导入及允许的更新。该权限不自动开放账号管理、规则发布、结算或付款，也不自动改变资料页面的手动编辑权限。

账号、计费规则、采摘记录、结算、付款不在本轮导入范围内。同名不同工号的工人不按姓名合并。

### 操作流程

1. 更新已有资料时，从系统下载资料表，在原行修改后上传；系统提供识别原资料所需编号，用户无需编写编号。
2. 预览新增、更新、跳过及错误，并显示更新前后差异，确认后才写入。
3. 工人引用的班组或产品引用的类别不存在时，预览列为待创建关联资料，经确认与本次资料一起创建，不静默创建。
4. 更新已有资料时，可选字段空白表示保留原值；必填字段缺失仍报错。需要清空内容时在原资料页面按现有权限操作。
5. 有任何错误行，整批不提交；全部修正并通过校验后才能确认。
6. 提交中发生错误，本次新增、更新和自动创建的关联资料全部撤销，原有数据不变。

筐型皮重更新不改变已保存采摘记录的皮重快照。预览后仍须在提交时重新校验，不以旧预览覆盖他人刚修改的数据。

批量导入要求联网。

## 五、打印快照与差异

- 点击每日核对表“打印”时自动保存本次完整内容、版式、操作人、生成时间和版本，无需另点留档。
- 浏览器取消打印后该版本仍留存；它证明生成过打印版本，不证明实际打印、签字或付款。
- 旧版永久保留生成时原样，不随当前采摘量、单价或模板变化而更新；打印当前账目生成新版。
- 历史快照仅供查看和对比，不提供重打；打印一律使用当前账目，并保存新版本。
- 老板和记录员均可查看历史打印快照，包括其中采摘量、工资，并按日期、班组查找。
- 记录员也可查看、打印往日所有工人的完整每日核对表，并在收回纸质签字表后登记“已签字”；仍校验核对内容是否变化，签字不代表付款。
- 查看旧版可对照当前账目，显示原值、现值以及相关修改人、时间和原因；不能将旧版改为当前值。
- 快照不重复计薪，不替代当前账目或已确认结算快照。
- 只改地块、总数量与工资不变时，无需重新签字；数量或工资变化继续要求重新核对签字，班组变更沿用既有规则。
- 历史快照查询、差异对比、当前核对表打印及快照生成要求联网，打印前处理本机待同步操作；无法替其他离线设备证明其数据全部上传。

## 六、整体确认的实施细则

以下细则随最终确认稿整体确认：

- 导入采用系统提供的 Excel 模板；缺少资料编号且名称可能重复时要求明确匹配，不静默覆盖已有资料。批次内重复标识报错，不任意保留一行。
- 成本分摊使用高精度计算，在原记录金额内分配到分，按确定性余数分配补齐尾差，避免累计多算或少算；报表分别标明公斤和筐，不混合求单位成本。
- 名单按日期、时段、工人、班组、产品、地块与实际数量组成匹配。实际数据变化后重算“已有记录”；变更和未作业说明若与后来实际记录矛盾，提醒重新核对，不掩盖实际作业。
- 地块归属单独更正与数量更正一样，在原记录及所选地块资料已下载时支持离线保存、联网提交，沿用权限、原因、版本和冲突核对；不得把未同步状态当后台已更正。

成本尾差使用最大余数法分配到分，相同余数按稳定的班组、地块顺序分配。后台保存数量组成，保留旧版操作摘要形状，兼容已有离线操作。

数据库以 Flyway V4 升级，旧数据归为未指定地块；原记录唯一键、结算快照保留。运行方式不变。
