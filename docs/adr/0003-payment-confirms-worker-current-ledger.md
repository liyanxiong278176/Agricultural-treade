# ADR 0003：付款时确认单人工资，余额随有效记录更新

状态：已接受，用户于2026-10-18通过逐项访谈及整体确认授权。

## 背景

原流程要求老板先确认整月结算，更正、晚传和调价后再确认补结算，最后才能付款。用户希望在记录员更正后直接看到新增未付并再次付款，同时保留历史账单及付款事实。

## 决策

工资页面的应发和未付按最新有效记录核算。取消独立确认入口，登记付款时在月份锁和同一事务中重新检查余额，仅为目标工人生成尚未确认的账目差额快照并保存付款与审计。保留原快照、原付款及旧内部差额口径用于历史核对。

付款ID仍绑定请求内容；查到原付款回执时直接返回原结果，不顺便确认之后的新更正。付款失败不留下快照。支付后的数量减少可以形成负未付，显示多付并线下处理。

## 取舍与结果

“已确认应发”不再仅指历史确认批次金额之和，而是用户约定的当前工资展示名称。当前金额可变与历史凭据不可变分别表达，减少操作的同时保留追溯依据。

不采用更正后静默改写旧快照，也不在单人付款时确认全月其他工人。旧确认接口保留兼容性，新前端不依赖它；未来若移除旧接口，应单独评估历史客户端及快照使用。
