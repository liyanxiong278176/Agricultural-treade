## 验收结论

核心业务链路可以运行：基础资料 → 手机录入 → 断网本机保存 → 恢复同步 → 月度核算 → Excel 导出 → 操作追溯。**尚不能判定为完全符合图片要求**：有一项已复现的接口输入校验缺陷，两项实现与图片规格的差异；安卓实机、局域网 HTTPS 和长时间弱网稳定性还没有在本次测试中验证。

本次只增加验收测试、隔离测试配置与报告，并修正两处过时测试断言，没有修改业务实现。

## 问题与规格差异

### BUG-01（P2）：规则缺少必填内容返回 HTTP 500

复现：管理员登录，向 `POST /api/rules/trial` 提交以下任一 body，均实际返回 500。

```json
{"rule":{"mode":"SEGMENTS","stages":[{"key":"main","label":"筐数","rate":"3"}]},"inputs":{"quantities":{"main":"5"},"weightUnit":"kg"}}
```

另外两种已复现输入是 `rule` 缺少 `mode`、或 `stages:[null]`。预期返回 400 和明确输入错误，实际返回泛化“服务暂时无法处理”。后端日志显示 `Pricing.validate` 在 12、15、16 行发生 NullPointerException：缺少 mode/type 时调用不接受 null 的 Set.contains，空阶段被直接解引用。

影响：正常界面录入路径不受本次测试影响，异常 API 输入不能正确处理。建议先校验 rule.mode、阶段对象与阶段 type 是否为 null，并将不完整规则统一转为 400。失败测试 API-10 保留，没有为了全绿降低期望。

原始证据：[接口响应](baseline-invalid-rule-responses.json)、最终报告中的 API-10，以及 `backend.out.log` 中的异常栈。修复后的响应单独见 [当前接口响应](invalid-rule-responses.json)。

### GAP-01（P2，规格差异）：记录员没有自由切换计件/计重

图片明确写出“选择工人 → 选择菜品 → 切换计件/计重 → 输入数量/重量 → 提交”。当前 `RecordEditor.vue` 使用 `activeRule(product,date)`，阶段类型由老板发布的产品规则决定；单一计件产品显示筐数，单一计重产品显示重量，组合规则按阶段显示。

该实现支持两种计费能力，但不等同于图片所写的同一菜品自由切换流程。若严格按图片验收，需补全模式选择以及对应单价规则；若保留当前设计，应先明确修改验收规格。

### GAP-02（P3，技术实现差异）：月度工作量没有 SQL GROUP BY 汇总

`Payroll.preview` 查询月份记录，逐条 `ledger.enrich` 计价，再使用 Java Map 按工人累加 pieces、weightKg 和 earned。SQL SUM 用于已结算、付款等金额。功能数值本次验证正确，但未实现图片指定的“后端用 SQL GROUP BY 和 SUM 自动计算每位工人的计件/计重总数”。不能以功能正确代替对指定技术方案的验证。

### TEST-01（已修正）：两项旧测试预期与在线直提行为不符

首轮既有浏览器测试 18 项中 16 项通过，2 项 `entry-feedback.spec.ts` 失败：在线保存实际显示“保存成功”，旧断言仍等待“已保存在本机”。在线删除旧断言也仍期待本机排队文案。依据实际在线接口成功回执及现有在线直提实现，将断言改为“保存成功”/“删除成功”，并复跑验证。没有改动产品行为。

首轮证据保留在 `browser-results.json`、`browser-report/`、`browser-artifacts/`；中间 31 项全通过结果保留在 `intermediate-browser-results.json`。

## 业务数值核对

- 计件：5 筐 × 3 元 = 15 元；再补录下午 2 筐后合计 7 筐、21 元。
- 先确认 15 元，晚传后已确认仍为 15 元、待补结算 6 元；补结算后 21 元。
- 同一付款 UUID 两次提交 10 元只记一笔；未付 11 元；再付 12 元被拒绝。
- 称重：20 斤 = 10 公斤；0.5 元/公斤得到 5 元；10 公斤/20 斤/10000 克试算一致。
- 重放同一采摘操作、六请求并发重放均只产生一条业务记录；不同操作抢同一业务键只有一个 ACCEPTED。
- `.xlsx` 通过 Python 标准库独立解析两张工作表，验收工人的筐数、应发、已确认、已付、未付与上述数值一致。见 [workbook-verification.json](workbook-verification.json)。
