## 角色和资料

老板管理工人、类别、具体产品、账号、计费规则、月度结算、付款、报表和日志；记录员负责采摘录入、补录、同步与允许范围的编辑恢复。工人不开账号。类别仅归类，没有默认计费规则或继承关系。姓名可重复，工号唯一，人员可停用而不抹除历史。

## 产品计费配置

每个产品独立保存规则版本。可配置 1–6 个有序阶段，每阶段包括名称、计件/计重、单价、适用数量下限/上限、阶段分配上限；顺序可以调整。计件仅使用筐，步长 0.5，计重单价以公斤配置。斤与克录入换算后核算。

首版支持两种明确的工作量来源，均由老板选择：

| 配置方式 | 记录员输入 | 计算方式 |
| --- | --- | --- |
| 分段登记 | 每阶段对应的互不重叠的数量 | 按顺序校验数量条件及上限，再汇总各部分精确报酬 |
| 总重量顺序分配 | 总重量及重量单位 | 各阶段依优先级从剩余重量取量；计件按老板配置的每筐公斤数折算到半筐，计重处理剩余或受上限限制的重量 |

“先计件再计重”只是一种可配例子。可以单一方式、调整顺序或增加阶段；不能把配置界面理解为任意文字、公式或脚本都可执行。总重量分配模式未配置每筐重量，或最后仍有未分配余量，会明确拒绝保存。手工分段模式由记录员按真实情况分配，不声称系统能证明同一工作量没有被重复填写。

整月追溯与自指定日期生效分别配置适用窗口。匹配多个版本时，使用适用窗口内**最后发布**的版本，保留历史。整月追溯不能降低已有劳动的工资；已存在记录时，结构不兼容的规则发布会被拒绝，并提示选择未来日期或保持兼容字段。改价引起的已结算差额不会改写历史快照。

数量最多六位小数，单价最多四位小数；组合记录先汇总阶段精确金额，再对该笔记录 HALF_UP 到分，工资总额为这些逐笔金额之和。

## 日期、唯一性与权限

实际采摘日期默认当天，上午/下午默认当前时段，记录员可按实际情况选择；上传时间不改变业务归属。过去日期新增属于补录，说明必填；当天备注选填，不允许未来日期。

数据库业务唯一键为 `worker_id + work_date + period + product_id`，包含已逻辑删除记录。上午和下午、不同产品、不同日期分别登记。多人记录同一工人合法，但同一业务键重复新增会拒绝；工作量增加通过更新总数处理。

记录员能查看全部历史采摘记录，并跨记录员更正数量或地块；往日及已结算更正必须填写原因并留痕。记录员删除限本人录入且尚未结算的记录，不限采摘日期，老板可删除全量未结算记录。任何角色均不能直接删除已结算记录。恢复误删无需老板审批：本人未结算历史记录或当天协作记录可恢复；已结算记录仍遵循结算保护。往日及已结算已有记录允许记录员直接更正，原因必填；已结算差额由老板另行补结算。

## 离线与冲突

首次联网登录并缓存资料与页面后才可离线。页面可离线刷新和重开；IndexedDB 内记录和发送操作在同一事务保存，界面仅在事务成功后报告本机已保存。本机数据按账号隔离，退出不清除原账号待传项。

每个操作有固定 UUID，重试保持 ID 和内容；服务端回执绑定账号与内容摘要。回执、业务变化、审计同事务提交。业务重复与网络重传分别处理，不以“UUID 不同”就认定是不同劳动。

离线重复新增先入库者保留，另一项保留冲突内容，记录员核对后舍弃或编辑原记录，不能自动相加或覆盖。版本冲突返回最新记录，保留用户输入；用户选择基于最新内容重改，或确认原输入重提，再次使用最新 version。关闭核对表单不丢弃冲突操作，只有确认保存新操作才在本机事务替换旧操作。

从未发送的本机新增可在同步中心编辑数量，在同一本机事务替换旧操作；一旦已尝试发送而结果未知，先同步确认，不直接改写请求内容。同步准备期间切换账号会中止旧队列发送，已经发出的请求始终使用原账号令牌。

在线操作直接提交后台，不需要进入同步中心。业务拒绝在当前页面显示并保留输入，不留待传项；在线版本冲突在原编辑表单中选择以最新数量重改或保留输入重提。离线或在线请求结果未知时保留固定操作标识，页面启动、恢复网络、回到前台、定时及手动触发积压操作同步；补传的业务拒绝停止自动重试并保留内容供核对。队列为一次最多 100 项的批量协议，逐项确认，支持部分成功。浏览器是否“在线”仅作提示，以实际请求结果判断后台是否可达。

离线时长未指定上限，不按天数清除待传项；不保证无限期离线、浏览器数据不被系统清理或锁屏/关页后台持续执行。

## 结算与付款

每月预览包含工人计件筐数、计重公斤数、当前核算、已确认应发、待结算差额、已付及未付。筐和公斤分别统计。

确认后建立不可改写的结算批次及逐记录快照。后到记录、追溯涨价、数量更正形成“当前金额 − 累计已确认金额”的差额，另建补结算。相同记录不会重复结算相同金额。价格发布、记录写入和结算使用适用月份行锁，记录更新另有 version 条件。

付款只登记已确认应发范围内实际支付的金额，支持分次、同一付款 ID 重试去重。付款方式含现金、微信、支付宝、银行转账、其他，不连接支付平台。若更正后出现已多付，未付余额会为负，需线下处理差额，当前没有自动退款和工资借款功能。付款登记不可直接删除或改写；正式付款纠错/冲正不在首版界面范围内。
